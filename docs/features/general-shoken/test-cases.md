# テストケース: 総合の所見

対応する要件は`docs/features/general-shoken/requirements.md`。所見管理画面・プロンプトひな形編集画面の既存ケースは各画面のテストケース表側でも更新している。

## 最低限のテスト(P0)

### GS-P0-01 総合タブのプロンプトに科目「総合」のメモだけが含まれる

- 優先度: P0
- 自動テスト: `e2e/general-shoken.spec.ts`
- 前提: 科目「国語」「総合」を登録済み。同じ生徒に国語のメモと総合のメモが1件ずつあり、いずれも共有区分は「共有する」
- 手順: 所見管理画面で対象期間を指定し、「総合の所見」タブで生徒の行の「AIで生成する」を開く
- 期待結果: プロンプトに総合のメモの本文が含まれ、国語のメモの本文は含まれない。学年はクラスの学年が自動で入り、生徒名は仮名コードに置き換わっている(実名は含まれない)

### GS-P0-02 学習タブの材料から科目「総合」が除外される

- 優先度: P0
- 自動テスト: `e2e/general-shoken.spec.ts`
- 前提: GS-P0-01と同じ
- 手順: 「学習の所見」タブで生徒の行の「AIで生成する」を開く
- 期待結果: プロンプトに国語のメモは含まれるが、総合のメモは含まれない(学習と総合で材料が重複しない)

### GS-P0-03 3種類の所見が互いに影響せず独立して保存される

- 優先度: P0
- 自動テスト: `e2e/general-shoken.spec.ts`
- 手順: 学習の所見を保存する → 総合タブに切り替えて総合の所見を保存する → 学習タブ・生活タブに戻る → 画面を再読み込みして総合タブを開く
- 期待結果: 総合タブの入力欄は最初空欄。総合を保存しても学習の所見の内容は変わらず、生活の所見は空のまま。再読み込み後も総合の所見が復元される。保存時のトーストは「(氏名)の総合の所見を保存しました」

### GS-P0-04 科目「総合」のメモがない場合は案内が出て手入力はできる

- 優先度: P0
- 自動テスト: `e2e/general-shoken.spec.ts`
- 前提: 科目「総合」の授業メモが1件もない(科目「総合」未登録の場合を含む)
- 手順: 「総合の所見」タブで生徒の行の「AIで生成する」を開く → その後、所見欄に手入力して保存する
- 期待結果: 「送信可能な総合の授業メモが存在しません」が表示され、プロンプト欄・生成ボタンは出ない。手入力した所見は従来どおり保存できる

### GS-P0-05 総合の所見用のひな形が独立して保存される

- 優先度: P0
- 自動テスト: `e2e/general-shoken.spec.ts`
- 手順: プロンプトひな形編集画面で「総合の所見用のひな形」だけを編集・保存 → 再読み込み → 総合タブでプロンプトを表示
- 期待結果: 総合用の内容が保存され、学習用・生活用は既定値のまま変わらない。総合タブのプロンプトに保存した内容が反映される

### GS-P0-06 他教員の総合の所見にアクセスできない

- 優先度: P0
- 自動テスト: `tests/db/rls.test.ts`
- 手順: 教員Aの生徒に総合の所見を保存し、教員Bのクライアントから読み取り・挿入・更新・削除を試みる
- 期待結果: 読み取りは0件、挿入はエラー、更新・削除は0件。RLSがテナント分離の唯一の防衛線として機能している

### GS-P0-07 エクスポートに総合の所見が含まれる

- 優先度: P0
- 自動テスト: `tests/db/rpc-export.test.ts`
- 手順: 総合の所見と総合用ひな形を保存した状態で全データをエクスポートする
- 期待結果: 生徒ごとに`generalComments`、`promptTemplate.generalContent`が含まれる。既存のキー(`comments`・`lifeComments`・`content`・`lifeContent`)も従来どおり出力される

### GS-P0-08 科目「総合」のメモしかない場合、学習タブでは材料0件になる

- 優先度: P0
- 自動テスト: `e2e/general-shoken.spec.ts`
- 前提: 科目「総合」の授業メモが1件だけあり、他教科のメモはない
- 手順: 「学習の所見」タブでAI生成セクションを開く → 「総合の所見」タブに切り替えて同じ操作をする
- 期待結果: 学習タブでは「送信可能なメモが存在しません」が表示される。同じメモが総合タブではプロンプトに含まれる

### GS-P0-09 所見を上書き保存すると「最終更新」が進む(BUG-009)

- 優先度: P0
- 自動テスト: `tests/db/schema.test.ts`(所見3種のupsert・メモの更新)。画面確認は手動
- 前提: 所見を1度保存済みの生徒がいる
- 手順: 同じ生徒の所見を書き換えて再度保存し、行の「最終更新」の表示を確認する(学習・生活・総合のいずれでも)
- 期待結果: 「最終更新」が保存した時刻に更新される。**本修正の適用前に保存された所見は、初回保存時の日時が入ったまま**で、次に保存した時点から正しい値になる

## 後で確認するテスト(P1〜P3)

### GS-P1-01 生徒を削除すると総合の所見も消える

- 優先度: P1
- 自動テスト: `tests/db/schema.test.ts`
- 手順: 総合の所見がある生徒を生徒名簿画面から削除する
- 期待結果: 確認ダイアログを経て、その生徒の総合の所見も物理削除される(`on delete cascade`)

### GS-P1-02 科目名を変更すると総合の材料が0件になる(既知の制約)

- 優先度: P1
- 自動テスト: 未対応(手動確認)
- 前提: 科目「総合」の授業メモがある状態
- 手順: 科目管理画面で「総合」を「総合的な学習の時間」にリネームし、総合タブでAI生成セクションを開く
- 期待結果: 「送信可能な総合の授業メモが存在しません」が表示される。**これは仕様どおりの挙動**(科目名の完全一致で絞り込むため。`docs/features/general-shoken/design.md` §7)。科目名を「総合」に戻せば材料が再び表示される

### GS-P1-03 総合の所見のAI直接生成

- 優先度: P1
- 自動テスト: 未対応(手動確認。実際のAI応答を確認するため)
- 前提: APIキー設定済み。総合のメモが2〜3件ある
- 手順: 総合タブで「AIで直接生成」を実行する
- 期待結果: 総合的な学習の時間の活動について書かれた所見が生成され、他教科の内容や記録にない活動が混ざっていない。学習・生活の所見とは異なる観点(調査・整理・発表など)に触れている

### GS-P2-01 タブが3つになっても横幅が崩れない

- 優先度: P2
- 自動テスト: 未対応(手動確認)
- 手順: タブレット幅(768px〜1279px)で所見管理画面を開く
- 期待結果: 3つのタブが折り返しや見切れなく表示され、クラス選択・対象期間の欄に重ならない

### GS-P2-02 ひな形編集画面が3つのフォームで扱いやすい

- 優先度: P2
- 自動テスト: 未対応(手動確認)
- 手順: タブレット幅でプロンプトひな形編集画面を開き、一番下の総合用フォームまでスクロールする
- 期待結果: 3つのフォームが縦に並び、それぞれの見出し・保存ボタン・プレースホルダー案内が対応関係を見失わずに読める
