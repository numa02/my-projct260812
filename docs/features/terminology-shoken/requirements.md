# 要件定義: 用語「所感」を「所見」に統一する

`docs/requirements.md` 全体(特にF9・F10・F11)で使っていた用語「所感」を、学校現場で通知表・指導要録に用いられる一般的な用語「所見」に置き換える。機能・データモデルの変更は伴わない、表記のみの仕様変更。

後続の改修「生活所見の記録」(学習の所見・生活の所見の2種類化)に先立ち、用語を先に確定させることが目的。

## 機能概要

1. 教員が目にするすべての画面文言(ナビゲーション、見出し、ボタン、トースト、確認ダイアログ、空状態・エラー文言)の「所感」を「所見」に置き換える
2. AIに渡すプロンプトの既定ひな形(`DEFAULT_PROMPT_TEMPLATE`)の「所感文」を「所見文」に置き換える
3. Hono経由のAI生成エンドポイントが返すエラーメッセージの「所感」を「所見」に置き換える
4. 要件定義・設計書・デザイン定義・機能別ドキュメント・モックアップ・`CLAUDE.md`・スキル定義の「所感」を「所見」に置き換える

## ユーザーストーリー

1. 教員として、通知表で使い慣れた「所見」という言葉でツールを操作したい。それは用語の読み替えをせずに済ませるためだ。

## 機能要件

- Given: ログイン済みの教員
  When: サイドナビゲーションを見る
  Then: 「所見管理」と表示される(旧「所感管理」)

- Given: 所見管理画面を開いている
  When: AI生成・保存・上書き確認・エラーなど任意の操作を行う
  Then: 表示される文言に「所感」は含まれず、すべて「所見」と表記される

- Given: プロンプトひな形を一度も保存していない教員
  When: AI生成を実行する、またはプロンプトひな形編集画面を開く
  Then: 既定ひな形の「所見文を作成してください」が使われる

- Given: 旧表記「所感」を含むプロンプトひな形をすでに保存している教員
  When: AI生成を実行する
  Then: 保存済みのひな形はそのまま使われる(ユーザーデータのため自動では書き換えない)

## 非機能要件

- DBスキーマ・RPC・APIのパス・エクスポートJSONのキーは変更しない(いずれも英語の識別子`comment`を使っており、表記変更の影響を受けないため)
- データ移行は発生しない

## スコープ外

- コード上の識別子(`student_comment`テーブル、`useStudentComments`、`components/comment/`、`/comments/class`のURL等)の改名。英語の`comment`は「所見」の訳語としても成立するため、改名コストに見合わない
- 適用済みマイグレーションファイル内のSQLコメント(適用済みファイルは書き換えない方針)
- 教員が保存済みのプロンプトひな形の中身の書き換え
- 所見の2種類化(学習/生活)・授業外メモの記録(後続の改修で扱う)
