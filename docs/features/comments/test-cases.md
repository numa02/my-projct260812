## TC-003: タブを切り替えてもクラス・生徒の選択状態が保持される

- 種別: 機能
- 観点: 正常系

### 前提条件

3. 「履歴」タブに切り替える
4. 「生成」タブに戻す

### 期待結果
- タブを切り替えてもクラス・生徒の選択状態が変わらない(選択し直しが不要)

### 確認した環境
- [ ] Chrome (Mac)

## TC-004: クラスを切り替えると生徒選択がリセットされる

- 優先度: P0
- 種別: 機能
- 観点: 正常系
- 自動テスト: `e2e/comments-skeleton.spec.ts`

### 前提条件
- クラスが2件あり、それぞれに生徒が登録済み

### 操作手順
1. クラスAで生徒を選択した状態から、クラスBに切り替える

### 期待結果
- 生徒選択が未選択に戻り、「生徒を選択してください」が表示される
- 生徒選択の候補がクラスBの生徒のみに絞り込まれる
- 生徒選択の`<select>`自体も「選択してください」のプレースホルダーが見た目上も選択された状態になっており、クラスBの先頭の生徒が誤って選択済みのように見えない(`docs/bugs.md` BUG-003再発防止。プレースホルダーがないと状態は未選択でも見た目は先頭の生徒が選択済みに見えてしまい、内容が表示されない理由が分かりにくくなる)

### 確認した環境
- [ ] Chrome (Mac)

## TC-102: Next.jsのクライアントサイド遷移直後にフォーム操作をしても正しく反映される(回帰確認)

- 優先度: P2
- 種別: 機能
- 観点: エッジケース
- 自動テスト: `e2e/comments-skeleton.spec.ts`(遷移直後のURL確定待ちを追加して安定化済み)

### 前提条件
- 生徒名簿画面から所感アイコンで遷移した直後

### 操作手順
1. 遷移直後、間を置かずにクラス選択を素早く切り替える

### 期待結果
- 遷移前のページの状態が残らず、新しいページのクラス・生徒選択が正しく反映される
- 備考: 開発中に検出したタイミング依存の不具合(`selectOption`がPlaywrightのナビゲーション待機と同期しないことによる見かけ上の不具合)であり、アプリ側のロジック自体には問題がないことをE2Eで確認済み。手動確認では素早い連続操作でも同様の挙動になるか念のため確認する

### 確認した環境
- [ ] Chrome (Mac)
