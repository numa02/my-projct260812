# 要件定義: 所感管理の再設計(期間の記憶・所感の単一化)

`docs/requirements.md` F9・F10・F11を変更する。特にF11の「所感は生徒と対象期間の組み合わせごとに1件保存され、過去の期間の所感を履歴として閲覧できる」という仕様を撤廃し、「所感は生徒ごとに最新の1件のみ保持する」方式に置き換える。`docs/requirements.md`の未決事項「所感の保存キーは生徒×期間(開始日・終了日の完全一致)としているため、前回と数日だけずれた期間で再生成した場合は別レコードとして保存される」(L497)を、期間の概念自体を廃止することで解消する。

## 機能概要

1. 所感管理画面の対象期間(開始日・終了日)を、クラスごとにDBへ保存し、次回以降その画面を開いたときに自動的に復元する
2. 所感のデータモデルから期間の概念を廃止し、生徒ごとに所感は常に最新の1件のみ保持する。対象期間の入力欄は画面に残すが、用途はAI生成時にどのメモを要約対象に含めるかを決めるパラメータに限定し、保存される所感の識別には使わない
3. 上記2に伴い、既存のF11後半で提供していた「過去の所感を期間ごとに一覧で見る」履歴閲覧機能を廃止する

## ユーザーストーリー

1. 教員として、所感管理画面を開くたびに対象期間を入力し直すのをやめたい。それはクラスごとに毎回同じ期間を指定するのが手間だからだ。
2. 教員として、保存したはずの所感が一覧に表示されないという状況をなくしたい。それは対象期間の指定が数日ずれるだけで、既に保存した所感が見えなくなってしまうのを防ぐためだ。

## 機能要件

### 対象期間の記憶(クラスごと)

- Given: あるクラスの所感管理画面を初めて開く(そのクラスについて対象期間を一度も保存したことがない)
  When: 画面が表示される
  Then: 対象期間の開始日・終了日はともに空欄で表示される

- Given: 所感管理画面である値の対象期間を入力する
  When: 開始日または終了日の入力欄の値が確定する(入力欄からフォーカスが外れる、またはdate inputの値変更イベントが発火する)
  Then: 入力された値が、表示中のクラスに紐づく対象期間として自動的にDBへ保存される。教員が明示的に保存操作を行う必要はない

- Given: あるクラスで対象期間を保存済みの状態で、いったん画面を離れて再度同じクラスの所感管理画面を開く
  When: 画面が表示される
  Then: 保存済みの対象期間(開始日・終了日)が自動的に入力欄に復元される

- Given: クラスAで対象期間を保存済みの状態から、画面上でクラスBに切り替える
  When: クラスBに切り替える
  Then: クラスBに紐づく対象期間(未保存であれば空欄)が表示される。クラスAの対象期間には影響しない

- Given: 対象期間の自動保存がサーバーエラーにより失敗する
  When: エラーが発生する
  Then: 入力欄の表示値は、直前にサーバーへの保存が確認できている値に戻る(サーバーが保存を確認していない値を表示し続けない)。画面に保存失敗の通知を表示する

- Given: 対象期間の終了日に、開始日より前の日付を入力する
  When: 入力欄からフォーカスが外れる(値が確定する)
  Then: 終了日の入力欄にエラーメッセージが表示され、自動保存は実行されない(不正な範囲を保存しない)

### 所感の単一化

- Given: ある生徒について所感を1件も保存したことがない
  When: 所感管理画面でその生徒の行を表示する
  Then: 所感入力欄は空欄で表示される

- Given: ある生徒について既に所感を保存済みである
  When: 所感管理画面でその生徒の行を表示する
  Then: 対象期間の入力欄の値に関わらず、保存済みの所感の内容がその生徒の所感入力欄に表示される(対象期間と所感の表示・非表示は連動しない)

- Given: ある生徒の所感入力欄に、AI生成・プロンプトコピー運用・手動入力のいずれかで内容を入力する
  When: その行の保存を実行する
  Then: その生徒の所感として保存される。その生徒について既に所感が保存済みであれば、既存の内容が新しい内容で上書きされる(生徒ごとに常に1件のみが保持される)。上書き確認ダイアログは表示しない(既存のF11の挙動を維持する)

- Given: 対象期間の入力欄に値が入力されている
  When: いずれかの生徒の行でAI生成セクションを開く
  Then: 対象期間内の「共有する」区分のメモのみをもとにしたプロンプトが組み立てられる(F9・F10の既存の挙動を維持する)。この対象期間の値は、生成後に所感を保存する際の識別情報としては使用されない

### 履歴閲覧機能の廃止

- Given: 所感管理画面である生徒の行を開いている
  When: 画面を操作する
  Then: 「過去の所感を見る」に相当する操作・表示は存在しない。所感入力欄には常にその生徒の最新の所感(保存済みであれば)のみが表示される

## 非機能要件

- **パフォーマンス**: 所感一覧の取得クエリが「生徒ごとに最新1件」というユニーク制約に基づく単純な取得になるため、既存(期間別に複数件保持し、対象期間で絞り込む方式)と比べてクエリは同等かそれ以下の負荷になる見込み
- **既存データへの影響(重要)**: 本機能のリリースには、既存の複数期間分の所感データを生徒ごとに最新の更新日時の1件へ集約し、他を削除する不可逆なデータマイグレーションを伴う。**実行前に本番DBの手動バックアップ(SQLダンプ)を取得することを前提とする**
- **認証・認可**: 既存のRLS(`student`→`class`経由で`teacher_id`を照合するポリシー、および`class`テーブル自体のRLS)をそのまま適用する。新規の認可ロジックは追加しない
- **ダウンタイム**: マイグレーション自体はSupabase(Postgres)上でオンライン実行可能であり、想定データ規模(1教員あたり数クラス×数十人)であればロック時間は軽微と見込まれる。ただし本番DBの実際の`student_comment`件数は未確認のため、リリース前に件数を確認したうえで所要時間を見積もることを推奨する
- **ロールバック**: コードのロールバックはVercelの再デプロイで完結するが、削除された過去の期間別所感データはバックアップなしでは復元できない

## スコープ外

- 過去の期間別所感を閲覧・参照する機能(履歴機能)の代替手段は設けない。必要になった場合は将来の別機能として再検討する
- 対象期間を教員アカウント単位(全クラス共通)で記憶する方式は採用しない。クラスごとに個別に記憶する
- 所感の保存に「この期間の所感として保存する」という明示的な期間ラベル付けの選択肢は設けない。保存は常に「その生徒の所感」を更新する操作として扱う
- 対象期間の自動保存に確認ダイアログ・アンドゥ機能は設けない

## 用語

| 用語 | 定義(変更後) |
|---|---|
| 所感 | 教員が指定した期間の「共有する」メモをもとに生成、または手動で作成する、目安の文字数のコメント文。**生徒ごとに常に最新の1件のみ保存される**(変更前は生徒×対象期間の組み合わせごとに1件だったが、本機能により期間の概念を廃止する)。保存後も再編集・再生成による上書きが可能で、内容を確定してロックする機能は持たない(この点は変更なし) |
| 対象期間 | 所感管理画面で指定する開始日・終了日。**所感生成時にAIへ送信するメモの絞り込み範囲としてのみ使用する**(変更前は保存される所感の識別キーの一部だったが、本機能によりその役割を廃止する)。クラスごとにDBへ自動保存され、次回以降その画面を開いたときに復元される |

## 未決事項

なし。本ドキュメント作成時点で技術的な論点はすべて確定している。ただし、既に本番環境で複数期間の所感を履歴として活用している教員が他にいる場合、履歴閲覧機能の廃止による影響について事前説明が必要かどうかは、本ドキュメントのスコープ外の運用判断とする。
