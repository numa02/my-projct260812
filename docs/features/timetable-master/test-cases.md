## TC-001: 一括モードでクラス選択+マスごとの科目選択が保存される(正常系)

- 優先度: P0
- 種別: 機能
- 観点: 正常系
- 自動テスト: `e2e/timetable-master.spec.ts`

### 前提条件
- クラス・科目が1件以上登録済み

### 操作手順
1. 一括モードでクラスを選択
2. 月曜1限に科目を設定
3. 起算日を入力して保存

### 期待結果
- 「時間割マスタを保存しました」が表示される
- 再読み込み後も入力内容(科目・起算日)が保持されている

### 確認した環境
- [ ] Chrome (Mac)

- モードを行き来しても保存済みデータ自体は変化しない(保存するまでは)

## TC-004: メモ保存後は起算日が読み取り専用になり、「年度を更新する」経由でのみ再設定できる

- 優先度: P0
- 種別: 機能
- 観点: 異常系
- 自動テスト: `e2e/timetable-master.spec.ts`

### 前提条件
- 起算日を設定済みで、授業記録(メモ)が1件以上保存されている

### 操作手順
1. `/timetable/master` を開く(起算日欄が無効化されていることを確認)
2. 「年度を更新する」→確認ダイアログで「続行」
3. 新しい起算日を入力して保存

### 期待結果
- メモ保存後は起算日欄が編集不可になり、案内文が表示される
- 「年度を更新しますか」の確認ダイアログには過去データが消えない旨の説明がある
- 続行後は起算日を編集でき、保存すると新しい起算日が反映される

### 確認した環境
- [ ] Chrome (Mac)

## TC-005: 一括モードのクラス選択も、初回表示時に既存データまたは先頭のクラスが自動選択される(`docs/bugs.md` BUG-002再発防止)

- 優先度: P0
- 種別: UI
- 観点: 正常系
- 自動テスト: 未対応(手動確認。クラス選択の`<select>`は元々「値が未選択でも見た目上は先頭が選択済みに見える」ため自動テストでは検知しづらく、目視確認が重要)

### 前提条件
- クラスが2件以上登録済み

### 操作手順
1. `/timetable/master` を開き、一括モードのクラス選択欄を確認する

### 期待結果
- 既存のマスにクラスが設定済みならそのクラスが、未設定ならクラス一覧の先頭が、明示的に選ばなくても選択された状態になっている
- 見た目上はクラスが選択されているのに保存時に「未設定」として扱われる、といった状態と表示のズレが起きない

### 確認した環境
- [ ] Chrome (Mac)
