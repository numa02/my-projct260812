# テストケース: 単元の記録と単元別の所見生成

対応する要件は`docs/features/memo-unit/requirements.md`。科目管理・授業記録・生徒別メモ一覧・所見管理の既存ケースは各画面のテストケース表側でも更新している。

## 最低限のテスト(P0)

### UN-P0-01 科目の行を開いて単元を登録・編集・削除できる

- 優先度: P0
- 自動テスト: `e2e/subjects.spec.ts`
- 前提: 科目「算数」を登録済み
- 手順: 科目管理画面で「算数」の行を開く → 単元「分数のかけ算」を追加 → 続けて「円の面積」を追加 → 「円の面積」を編集して名前を変える → 編集した単元を削除する
- 期待結果: 行を開く前は単元の欄が出ない。開くと最初は「まだ単元が登録されていません」。追加のたびに入力欄がクリアされ、登録順に並ぶ。編集・削除はそれぞれトーストで成功が通知され、削除確認の本文に「この単元を使っているメモは単元未設定に戻ります(メモは削除されません)」が含まれる。削除しても残りの単元は消えない

### UN-P0-01b 貼り付けで単元をまとめて登録できる

- 優先度: P0
- 自動テスト: `e2e/subjects.spec.ts`
- 前提: 科目「算数」を登録済みで、単元は0件
- 手順: 科目の行を開く → 「貼り付けで一括登録」を開く → 「単元名<TAB>時数」の3行を貼り付けて「取り込む」
- 期待結果: 貼り付けた順に3件の単元が一覧に並ぶ。**時数の列は単元として登録されない**。「3件の単元を登録しました」のトーストが出て、貼り付け欄がクリアされる。貼り付け欄が空のとき「取り込む」は押せない

### UN-P0-01c 一括登録は登録済みの単元をスキップする

- 優先度: P0
- 自動テスト: `e2e/subjects.spec.ts`
- 前提: UN-P0-01bの続き(「分数のかけ算」が登録済み)
- 手順: 「分数のかけ算」と未登録の「小数のかけ算」を貼り付けて取り込む → さらに「分数のかけ算」だけを貼り付けて取り込む
- 期待結果: 1回目は「小数のかけ算」だけが追加され、「分数のかけ算」は1件のまま。2回目は「登録済みの単元のみだったため、新規追加はありませんでした」が出て件数が変わらない

### UN-P0-02 科目の削除確認に単元も消えることが明示される

- 優先度: P0
- 自動テスト: `e2e/subjects.spec.ts`
- 手順: 科目管理画面で、メモで使われていない科目の削除を実行する
- 期待結果: 確認ダイアログの本文に「この科目に登録済みの単元もまとめて削除されます」が含まれる。続行すると科目とその単元が削除される

### UN-P0-03 単元を選んでメモを保存でき、開き直すと単元が選択済みになる

- 優先度: P0
- 自動テスト: `e2e/memos-record.spec.ts`
- 前提: 月曜1限に科目「国語」が設定済み。科目「国語」に単元「詩を読もう」を登録済み
- 手順: 授業記録画面で月曜の日付・1限を開き、単元「詩を読もう」を選ぶ → 生徒の行を開いてメモを保存する → 同じ日付・時限で画面を開き直す
- 期待結果: 単元のプルダウンには「選択しない」とその科目の単元が並ぶ。開き直したとき、保存済みメモの単元が初期選択されている

### UN-P0-04 単元を変更するとそのコマの保存済みメモもまとめて更新される

- 優先度: P0
- 自動テスト: `e2e/memos-record.spec.ts`
- 前提: UN-P0-03の状態(「詩を読もう」でメモが1件保存済み)。同じ科目に単元「物語を読む」も登録済み
- 手順: 授業記録画面で同じコマを開き、単元を「物語を読む」に変更する → 生徒別メモ一覧でそのメモを確認する
- 期待結果: 「このコマの1件のメモの単元を更新しました」のトーストが出る。開き直すと「物語を読む」が選択済みになり、生徒別メモ一覧の見出しも「物語を読む」になる

### UN-P0-05 単元が未登録の科目でも従来どおりメモを記録できる

- 優先度: P0
- 自動テスト: `e2e/memos-record.spec.ts`
- 前提: その時限の科目に単元を1件も登録していない
- 手順: 授業記録画面を開き、生徒の行を開いてメモを保存する
- 期待結果: 単元のプルダウンの代わりに「まだ単元が登録されていません(科目管理画面で登録できます)」が表示される。メモの保存は従来どおり成功する

### UN-P0-06 生徒別メモ一覧の見出しに単元名が出る

- 優先度: P0
- 自動テスト: `e2e/memos-students.spec.ts`
- 前提: 単元付きのメモと単元未設定のメモがそれぞれ1件以上ある
- 手順: 生徒別メモ一覧を「日付順」で表示する
- 期待結果: 単元付きのメモは「日付 ・ 時限 ・ 教科 ・ 単元名」、単元未設定のメモは「日付 ・ 時限 ・ 教科」で表示される。生活メモには単元の表示が出ない

### UN-P0-07 教科別表示で、単元付きメモがある教科だけ単元の小見出しに分かれる

- 優先度: P0

- 期待結果: 国語の下に単元の小見出しが出る。算数には小見出しが作られず、従来どおりメモがそのまま並ぶ

### UN-P0-08 同じ教科で混在すると「単元未設定」が最後に来る

- 優先度: P0

- 期待結果: その教科の小見出しが「単元名 → 単元未設定」の順に並ぶ

### UN-P0-09 単元ごとのカードが並び、選んだ案が連結して所見欄に反映される

- 優先度: P0
- 自動テスト: `e2e/memo-unit.spec.ts`
- 前提: 対象期間内に、2つの単元のメモと単元未設定のメモがそれぞれ共有区分「共有する」である
- 手順: 所見管理画面の「学習の所見」タブで生徒の行の「AIで生成する」を開く → 「単元ごとに生成」に切り替える → 2つの単元にAIの応答を貼り付けて案にする → 「選択した案を所見欄に反映」を実行する → 保存する
- 期待結果: 既定は「まとめて生成」。切り替えると単元のカードが日付順に並び、「単元未設定」が最後に来る。各カードのプロンプトにはその単元のメモだけが含まれ、実名は含まれない。案を貼り付けたカードは自動でチェックが入り、案のないカードはチェックできない。反映すると2件の本文が空行区切りで連結される。保存すると作成方法が「AI生成(プロンプトコピー運用)」になる

### UN-P0-10 カード内で編集した内容が反映される

## 後で確認するテスト(P1〜P3)

### UN-P1-01 「すべての単元を生成」が順次実行され、途中の失敗でも続行する

- 優先度: P1
- 自動テスト: 未対応(手動確認。実際のAPIキーと外部プロバイダが必要)
- 前提: APIキーを設定済みで、対象期間内に3つ以上の単元のメモがある
- 手順: 「単元ごとに生成」で「すべての単元を生成」を実行する
- 期待結果: 何件目まで終わったかが表示されながら単元が順に生成される。失敗した単元のカードにだけエラーが出て、残りの単元の生成は続く。自動で再試行はされず、そのカードの「生成」を押し直せば再実行できる

### UN-P1-01b 一括登録の失敗時に貼り付けた内容が残る

- 優先度: P1
- 自動テスト: 未対応(手動確認。通信を切って実行する)
- 手順: 「貼り付けで一括登録」に単元名を入力した状態で通信を切り、「取り込む」を実行する
- 期待結果: エラーのトーストが出て、**貼り付けた内容は欄に残る**(F13)。自動で再送はされず、通信を戻して押し直せば登録できる。部分的に入った状態にはならない

### UN-P1-01c 単元名に半角カンマ・タブが含まれる場合(既知の制約)

- 優先度: P1
- 自動テスト: 一部`shared/parse-unit-list.test.ts`(タブ優先の判定)
- 手順: 「大きい数,くらべ方」のように半角カンマを含む単元名を1行で貼り付けて取り込む
- 期待結果: カンマの前までが単元名になる(既知の制約。`design.md` §7)。全角読点「、」なら切れない。切れてしまった場合は鉛筆ボタンの編集で直せる

### UN-P1-02 単元ごとの案は保存されず、閉じると消える

- 期待結果: 案は残っていない(保存しない仕様。`requirements.md`のスコープ外に記載)

### UN-P1-03 直接生成とプロンプトコピーの案が混在した場合の作成方法
