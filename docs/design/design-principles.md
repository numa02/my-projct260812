# デザイン原則:週間時間割・生徒メモ・所見自動生成ツール

## ターゲットユーザー

- 20〜40代中心の教員。ITにある程度慣れており、専門用語や複雑な操作を避ける必要はないが、学習コストの高いUIは避ける
- 利用デバイスはPC・タブレット(スマートフォンは対象外)
- 利用シーンが2種類あり、両方に配慮する
  - **速記シーン**: 授業の合間・休み時間の数分、放課後にまとめて入力。少ないステップ数・大きいタップ領域・迷わない導線を優先する
  - **熟考シーン**: 学期末に所見文をじっくり作成・見直す。情報の見やすさ・比較しやすさ・読みやすい文字組みを優先する

## 与えたい印象

**シンプル・静か・信頼感**

参考: Notion、craft.do(https://www.craft.do/ja)── 余白を活かしたレイアウト、抑制されたトーン、上品なタイポグラフィ

## デザイン原則

- **静けさを優先する**: 装飾よりも余白を優先する。生徒の記録という性質上、画面は落ち着いて集中できるものにする
- **速記性を優先する**: 授業の合間に使う画面(授業記録・週次時間割)では、情報量よりも入力の速さ・タップのしやすさを優先する
- **信頼感を優先する**: 賑やかさよりも一貫性を優先する。色数を絞り、同じ操作は同じ見た目・同じ位置に統一する
- **実務ツールらしい素直さを優先する**: 個性的な演出よりも、迷わず使える標準的なUIパターンを優先する
- **可読性を優先する**: 所見文などまとまった文章を扱う画面では、装飾よりも文字の読みやすさ(行間・文字サイズ・コントラスト)を優先する

## トーン&ボイス

- マイクロコピーは丁寧語(です・ます調)で、簡潔に
- エラーメッセージは何が起きたか・次に何をすればよいかを具体的に伝える(要件定義書のエラー文言の丁寧さを踏襲する)
- 生徒の個人情報やAI送信に関する注意文は、脅すような表現を避けつつも見落とされない程度の視認性を持たせる
- 絵文字・カジュアルな言い回しは使わない(実務ツールとしての信頼感を損なうため)

## やらないこと(避けたいデザイン)

- 子供っぽい配色・キャラクター的なイラスト・ポップな装飾
- 企業SaaS然とした無機質で作り込まれすぎたビジュアル(過剰なグラデーション、大仰なマーケティング的ヒーローセクションなど)
- 1画面に情報を詰め込みすぎるレイアウト(タブや折りたたみで段階的に情報を出す)
- ダークモード(MVPではライトモードのみに絞り、実装・デザイン工数を抑える)

### 例外:時間割マスタ設定画面(教科担任制モード)

曜日×時限(最大30マス)×科目・クラスの2項目で、最大60個の入力コントロールが1画面に並ぶ。「情報を詰め込みすぎない」原則とは緊張するが、以下の理由で現状のまま許容する(意図的な例外として明記する)。

- 利用頻度が低い設定画面であり(年度替わり・時間割変更時のみ)、授業記録・週次時間割のような速記性が求められる画面ではない
- マスごとに科目・クラスを俯瞰して整合性を確認しながら入力する性質上、タブや折りたたみで分割すると全体像が見えづらくなり、かえって誤入力のリスクが上がる
- 今後、実際の利用感で密度が問題になった場合は、曜日ごとのタブ分割等を再検討する

## アクセシビリティ方針

- 文字色と背景のコントラスト比はWCAG AA相当を満たす
- 色だけで意味を伝えない(共有区分やエラー状態などは色に加えてラベル・アイコンでも判別できるようにする)
- タップ領域はタブレット操作を想定し、小さすぎるボタン・リンクを避ける
- フォントサイズは本文14px以上を目安とし、所見文などまとまった文章を読む画面ではより余裕を持たせる
