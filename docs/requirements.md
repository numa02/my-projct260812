# 要件定義書:週間時間割・生徒メモ・所感自動生成ツール

## 概要・目的

学校の教員が週間時間割(1〜6時間目)を作成し、授業ごとに生徒別のメモを記録できるWebツールを提供する。学期末には、蓄積したメモをもとにAIが生徒一人ひとりの所感文を自動生成し、教員が内容を確認・編集してから所感として保存する。所感は生徒と対象期間(学期等)の組み合わせごとに個別に保存され、学期をまたいで複数期間分の所感を記録・参照できる。所感に「確定」のような別状態は設けず、保存後もいつでも再編集・再生成できる。

教員はメールアドレスとパスワードでアカウントを作成してログインし、データはSupabase(PostgreSQL)に保存される。フロントエンドはNext.js、バックエンドはHonoで構築し、ホスティングはVercelを用いる(当初はCloudflare Pages/Workersを想定していたが、Next.js 16の`proxy.ts`がNode.jsランタイム固定になったことに伴う非互換のためVercelに変更。詳細は`docs/tasks.md` T-005/T-079参照)。ログインすれば自宅PC・学校PC・タブレットなど複数の端末から同じデータにアクセスできる。1つのアカウントは1人の教員に対応し、他の教員のデータにはアクセスできない(教員間でのデータ共有・共同編集は行わない)。

本ツールが解決する課題は、学期末に教員が生徒一人ひとりの所感文(通知表等に記載する文章)を作成する際、日々の観察記録が残っていないために記憶に頼って作成せざるを得ない負担である。授業のたびに短いメモを残しておくことで、学期末の所感作成をAIによる下書き生成で支援する。学期の区切り方(3学期制、前期・後期制等)は学校によって異なるため、所感生成の対象期間は固定の「学期」ではなく、教員が任意に指定する期間とする。

## ターゲットユーザー

- 小学校・中学校・高等学校の教員
- 1人で複数のクラス、複数の科目を担当する教員(教科担任制を含む)
- 基本的なPC操作(文字入力、クリック)ができる教員
- 想定するデータ規模は1教員あたり数クラス×数十人の生徒
- 利用デバイスはPCおよびタブレット。同一教員が複数端末(自宅PC・学校PC・タブレット等)からログインして使うことを想定する
- インターネットに接続されたブラウザ(Chrome、Edge、Safariの最新版)を利用する教員
- 現時点での想定利用規模は個人利用〜身内の少数(数人程度)によるテスト運用

## ユーザーストーリー

1. 教員として、クラスを作成し複数のクラスを切り替えて管理したい。それは教科担任制で複数クラスを受け持つ場合にも、クラスごとにデータを分けて扱うためだ。
2. 教員として、生徒名簿をCSVまたはテキストの貼り付けで一括登録したい。それは生徒を1人ずつ手入力する手間を省くためだ。
3. 教員として、標準となる週間時間割をマスタとして1回設定したい。それは毎週同じ時間割を入力し直す手間を省くためだ。
4. 教員として、時間割の起算日を設定し、今日が第何週かをひと目で確認したい。それは長期休業や行事をはさんでも週の感覚をすぐ把握するためだ。
5. 教員として、特定の週だけ時間割がマスタと異なる場合に、その週の時間割上で個別に変更したい。それは行事等による時間割変更をマスタに影響させずに反映するためだ。
6. 教員として、授業のたびに生徒ごとのメモを日付・時限付きで記録したい。それは学期末に生徒の様子を振り返るための材料を蓄積するためだ。
7. 教員として、授業と直接関係のない内容や機微な内容のメモをAIへの送信対象から除外したい。それは生徒のプライバシーを守るためだ。
8. 教員として、特定の生徒の過去のメモを日付順または教科別に一覧・編集・削除したい。それは所感を作成する前に、その生徒の変化を確認するためだ。
9. 教員として、所感文を生成する際にもとにするメモの期間を指定したい。それは3学期制、前期・後期制など学校ごとに異なる区切りに合わせて所感を作成するためだ。
10. 教員として、生成する所感文の目安の文字数を指定したい。それは提出先(通知表の書式等)によって求められる文字数が異なるためだ。
11. APIキーを設定した教員として、所感文をボタン一つで生成したい。それはツール内で完結して所感の下書きを得るためだ。
12. APIキーを持たない教員として、所感生成用のプロンプトをコピーして外部のAIチャットサービスに貼り付けたい。それはAPIキーがなくてもAIによる所感生成の支援を受けるためだ。
13. 教員として、AIが生成した所感文を確認し、必要に応じて修正したい。それはAIの出力をそのまま使わず、内容の正確性を教員自身が担保するためだ。
14. 教員として、AIを使わずに所感文を最初から自分で入力したい。それはネット環境がない場合やAIを使いたくない場合にも所感を記録するためだ。
15. 教員として、メールアドレスとパスワードでアカウントを作成し、自宅PC・学校PC・タブレットなど複数の端末から同じデータにログインしてアクセスしたい。それは端末を問わず同じデータを参照するためだ。
16. 教員として、生徒の実名が外部のAIサービスに送信されないようにしたい。それは生徒の個人情報を保護するためだ。
17. 教員として、所感生成の前に生徒の仮名コードを確認したい。それはプロンプトコピー運用で外部AIサービスに渡すプロンプトにどの仮名コードが使われるかを事前に把握し、複数の生徒を扱う中で取り違えないようにするためだ。
18. 教員として、所感生成用のプロンプトのひな形を自分用に編集したい。それは学校や自分の書き方の癖に合わせて所感の文体・観点を調整するためだ。
19. 教員として、生徒ごとに過去に作成した所感を期間ごとに一覧で確認したい。それは学期をまたいで所感の記録を振り返り、必要なら修正するためだ。
20. 教員として、登録済みのクラスの学年やクラス表示名を後から修正したい。それは入力ミスを訂正するためだ。
21. 教員として、自分が教える科目をあらかじめ登録しておきたい。それは時間割やメモの入力のたびに科目名を自由入力して表記がぶれるのを防ぐためだ。
22. 教員として、年度が変わったタイミングで起算日を再設定したい。それは新しい学年度の週番号を正しく数え直すためだ。
23. 教員として、生徒ごとのメモ・所感を含む全データをファイルとして保管しておきたい。それは生徒やクラスを削除した後も記録を参照できるようにし、また無料プランでは自動バックアップが行われないため、自分の判断でデータを保全するためだ。

## 機能要件

### F1. クラス管理

クラスをまたいで常時「選択中のクラス」を保持するグローバルな仕組み(全画面共通のクラス切替)は設けない。学級担任制だけでなく教科担任制(1人の教員が複数クラスを掛け持つ)の教員も多く、特定の1クラスを常に前提にする設計はなじまないため。クラスに紐づく操作が必要な画面(生徒名簿(F2)、生徒別メモ一覧(F7)、所感管理画面(F9・F10・F11)等)は、それぞれの画面内で個別にクラスを選択する。

- Given: クラス管理画面を開いている
  When: 学年・クラス表示名(例:「3年2組」「ひまわり組」)を入力してクラスを作成する
  Then: 新しいクラスがクラス一覧に追加され、内部管理用の組番号(同一学年内でのクラス作成順の連番)が自動的に付与される

- Given: クラス管理画面で、学年の代わりに「特支」を選択してクラス表示名を入力する
  When: 作成を実行する
  Then: 学年が「特支」のクラスとしてクラス一覧に追加される。特別支援学級等、学年をまたぐ生徒を1つのクラスにまとめて登録したい場合に使う。組番号の自動採番は「特支」を1つの学年区分として扱う(通常の学年の連番とは別に、「特支」内での作成順で採番する)

- Given: クラス管理画面の一覧で、登録済みのクラスのクラス表示名を編集する(学年は変更しない)
  When: 変更を保存する
  Then: クラス表示名のみが更新される。組番号・仮名コードは変更されない

- Given: クラス管理画面の一覧で、登録済みのクラスの学年(通常の学年⇔「特支」を含む)を変更する
  When: 変更を保存する
  Then: 変更後の学年区分(通常の学年または「特支」)内で未使用の組番号が新たに採番され、以降の仮名コード生成にはこの新しい学年・組番号が使われる。変更前に外部のAIサービスへ送信済みのプロンプトや、既存のメモ・所感に表示されている過去の仮名コードの表記は遡って変更されない。学年変更時は「学年を変更すると、以降このクラスの仮名コードが変わります。過去にAIへ送信済みの仮名コードはそのままです」という確認ダイアログを表示し、続行した場合のみ変更を保存する

- Given: クラス管理画面の一覧で、生徒が1人も登録されていないクラスの削除を実行する
  When: 削除確認ダイアログで続行を選択する
  Then: そのクラスが一覧から削除される。組番号は再利用せず欠番のまま進める(仮名コード生成が組番号に依存するため、過去のメモ・所感の仮名コードとの整合性を保つ)。削除対象のクラスが時間割マスタまたはいずれかの週の個別変更でマスに割り当てられている場合、削除確認ダイアログに「このクラスは時間割で使用中です。削除すると該当するマスは未設定に戻ります」という旨を表示し、続行するとそれらのマスの割当は自動的に「未設定(空きコマ)」に戻ってから、クラス自体が削除される

- Given: クラス管理画面の一覧で、生徒が1人以上登録されているクラスの削除を実行する
  When: 削除を実行する
  Then: 削除は行われず、「生徒が登録されているため削除できません。先に生徒名簿から生徒を削除してください」というエラーが表示される

### F2. 生徒名簿インポート

- Given: 生徒名簿画面を開いている
  When: 画面内のクラス選択でクラスを選ぶ
  Then: 選んだクラスの生徒一覧が表示され、以降のインポート・編集・削除はそのクラスに対して行われる

- Given: クラスが1件も登録されていない状態で生徒名簿画面を開く
  When: 画面が表示される
  Then: 生徒一覧・インポート欄は表示されず、「まだクラスが登録されていません」という案内とクラス管理画面(F1)への導線が表示される

- Given: 生徒名簿画面のCSVアップロード欄または貼り付け欄にデータを入力している
  When: インポートを実行する
  Then: 各行の出席番号と氏名の組が、選択中のクラスの生徒一覧に登録される。列順は「出席番号,氏名」固定、ヘッダー行なし前提とする。CSVアップロード・貼り付けの両方とも同一フォーマットで、区切り文字はカンマ/タブを自動判定する。文字コードはUTF-8を想定する

- Given: 貼り付けたデータのある行で氏名または出席番号が空である
  When: インポートを実行する
  Then: その行は生徒として登録されず、エラー行として画面に一覧表示される

- Given: 貼り付けたデータの中に、選択中のクラス内で出席番号が重複する行がある
  When: インポートを実行する
  Then: 重複する行は登録されず、エラー行として画面に一覧表示される

- Given: 生徒名簿画面で登録済みの生徒の氏名または出席番号を編集する
  When: 変更を保存する
  Then: 生徒情報が更新される。編集後の出席番号が同じクラス内の他の生徒と重複する場合は保存できず、インポート時と同様にエラーが表示される

- Given: 生徒名簿画面で生徒の削除を実行する
  When: 削除を実行しようとする
  Then: 「この生徒を削除すると、記録済みのメモ・所感もすべて完全に削除され、復元できません」という確認ダイアログを表示する。続行した場合のみ、その生徒と、その生徒に紐づくメモ・所感がすべて物理的に削除される。キャンセルした場合は何も削除されない(生徒を削除する前に、必要な記録はデータエクスポート(F14)で保全しておくことができる)

- Given: 生徒名簿画面で生徒一覧を表示している
  When: 一覧が表示される
  Then: 各生徒の氏名に併記する形で、その生徒の仮名コードが表示される

- Given: 生徒名簿画面で生徒一覧を表示している
  When: いずれかの生徒の行(氏名部分)をクリックする
  Then: その生徒を選択済みの状態で生徒別メモ一覧画面(F7)に遷移する

### F3. 科目管理

- Given: 科目管理画面を開いている
  When: 科目名を入力して登録する
  Then: 新しい科目が科目一覧に追加される。科目は教員1人につき1つの共通の一覧であり、クラスや学年には依存しない

- Given: 科目管理画面の一覧で、登録済みの科目名を編集する
  When: 変更を保存する
  Then: 科目名が更新され、既にその科目を参照している時間割マスタ・週次時間割の個別変更・メモの表示上の科目名も新しい名称に更新される(科目はIDで参照されるため)

- Given: 科目管理画面の一覧で、時間割マスタ・週次時間割の個別変更・メモのいずれでも使用されていない科目の削除を実行する
  When: 削除確認ダイアログで続行を選択する
  Then: その科目が削除される

- Given: 科目管理画面の一覧で、時間割マスタ・週次時間割の個別変更・メモのいずれかで使用されている科目の削除を実行する
  When: 削除を実行する
  Then: 削除は行われず、「この科目は時間割またはメモで使用されているため削除できません」というエラーが表示される

- Given: 科目が1つも登録されていない状態で、時間割マスタ設定画面(F4)または授業記録画面(F6)を開く
  When: 科目の選択欄を表示する
  Then: 選択できる科目がない旨が表示され、先に科目管理画面で科目を登録するよう案内される

### F4. 時間割マスタ設定

時間割マスタは教科担任制(1人の教員が複数クラスの授業を持つ)を考慮し、クラスに紐づくデータではなく**教員1人につき1つ**のデータとする。曜日・時限のマス(スロット)ごとに「科目」と「クラス」の両方を割り当てる。科目は科目管理(F3)で事前に登録したものの中から選択する(自由入力ではない)。

入力の手間を減らすため、画面には次の2つの入力モードを用意する。どちらのモードで入力しても、保存されるデータの構造(スロットごとに科目・クラスを持つ)は同じであり、モードは入力方法の違いにすぎない。

- **一括モード(初期値)**: 単一のクラスだけを担任する教員(小学校等)向け。画面上部でクラスを1つ選択すると、そのクラスが全スロットに一括で適用される。マスごとには科目のみを選択すればよい
- **教科担任制モード**: 複数クラスを受け持つ教員向け。マスごとに科目とクラスをそれぞれ個別に選択する

- Given: 時間割マスタ設定画面で、曜日(月〜金)と時限(1〜6時間目)の各マスへの科目・クラスの割り当てと週の起算日(基準となる開始日)を入力して保存する
  When: 保存を実行する
  Then: マスタの時間割(マスごとの科目・クラス)と起算日が保存され、起算日を含む月曜始まりの週が「第1週」として、以降表示される週次時間割の週番号がこの起算日を基準に計算される。起算日は教員1人につき1つであり、クラスごとには持たない

- Given: 一括モードで、画面上部のクラスを選択し、各マスの科目を入力して保存する
  When: 保存を実行する
  Then: 選択したクラスが全マスに適用され、マスタの全スロットが同一のクラス・入力した科目で保存される

- Given: 教科担任制モードで、マスごとに異なる科目・クラスを選んで保存する
  When: 保存を実行する
  Then: マスごとに指定した科目とクラスがそれぞれ保存され、他のマスには影響しない

- Given: 一括モードと教科担任制モードを切り替える
  When: 切り替えを行う
  Then: 切り替えただけでは保存済みのデータは変更されない。既存のマスごとの科目・クラスの入力内容は保持されたまま、表示方法(クラス選択欄が画面上部にまとまるか、マスごとに表示されるか)のみが変わる

- Given: 教科担任制モードでマスごとに異なるクラスが設定されている状態から一括モードに切り替え、画面上部でクラスを選択して保存を実行する
  When: 保存を実行しようとする(かつ、選択したクラスと異なるクラスが設定されているマスが1つ以上存在する)
  Then: 「保存すると、マスごとに設定されているクラスがすべて『(選択したクラス名)』に統一されます。続行しますか」という確認ダイアログを表示する。続行した場合のみ全マスのクラスが選択したクラスで上書きされ、キャンセルした場合は保存を中断し既存の内容を変更しない。選択したクラスと既存の全マスのクラスが既に一致している場合は、上書きが実質的に発生しないため確認ダイアログを表示しない

- Given: 週の起算日を入力せずに時間割マスタ設定の保存を実行する
  When: 保存を実行する
  Then: 起算日が未入力である旨のエラーが表示され、保存されない(週次時間割画面は起算日が保存されるまで参照できない)

- Given: 起算日を保存済みだが、授業記録(メモ)がまだ1件も保存されていない
  When: 時間割マスタ設定画面で起算日を変更して保存する
  Then: 起算日が新しい値に更新され、以降表示される週次時間割の週番号はこの新しい起算日を基準に再計算される

- Given: 起算日を保存済みで、かつ授業記録(メモ)が1件以上保存されている
  When: 時間割マスタ設定画面を開く
  Then: 起算日の入力欄は通常は変更不可(読み取り専用)として表示され、「授業記録が開始されているため起算日は変更できません」という説明とあわせて、「年度を更新する(起算日を再設定する)」という別操作への導線が表示される

- Given: 起算日が変更不可の状態で「年度を更新する(起算日を再設定する)」を選択する
  When: 「年度を更新すると、今日以降の週番号の数え方が新しい起算日を基準に変わります。過去に記録した授業記録・メモ・所感はそのまま残り、削除されません」という確認ダイアログで続行を選択する
  Then: 起算日の入力欄が一時的に編集可能になり、新しい起算日を入力して保存できる。保存後は新しい起算日を基準に、以降表示される週次時間割の週番号が再計算される。この操作はクラス・生徒・科目のデータには一切影響しない(年度替わりのクラス作り直しは別途手動で行う運用)

- Given: 時間割マスタ設定画面で、一部のマスの科目を未入力のまま保存を実行する
  When: 保存を実行する
  Then: 未入力のマスは「科目未設定」として保存される。起算日とは異なりエラーにはならず、保存は成功する

- Given: あるマスに既に科目・クラスが割り当てられている
  When: そのマスに別の科目・クラスを選び直して保存する
  Then: マスタの割当が新しい内容で上書きされ、以降新しく表示される週にはこの内容が反映される

- Given: あるマスについて、週次時間割で個別変更(F5)が設定されている週が存在する
  When: 時間割マスタ設定画面で、そのマスの科目・クラスを編集して保存する
  Then: 個別変更のうち、保存後のマスタの内容と一致した項目(科目・クラスのどちらか、または両方)だけがマスタ参照に戻る。科目・クラスの両方が一致した場合はその週・そのマスの個別変更自体が削除され、「変更あり」表示も消える。一方だけが一致した場合は、一致した項目のみマスタ追従に戻り、残りの項目は個別変更されたままになるため「変更あり」表示は残る

### F5. 週次時間割の閲覧・編集

- Given: 週次時間割画面を開いている
  When: 画面が表示される
  Then: 起算日から計算された現在の週番号と日付範囲(例:「8/3〜 第1週」)、およびマスタの内容(マスごとの科目・クラス)が自動的に入力された時間割が表示される。この時間割は教員1人につき1つの共通データであり、担当する全クラス分をまとめた1週間分のスケジュールとして表示される

- Given: 週次時間割画面で週番号または日付を指定して週を選択する
  When: 選択を実行する
  Then: 指定した週にジャンプし、その週の時間割(個別変更があればその内容、なければマスタの内容)が表示される

- Given: ある週の時間割画面で、特定のマスの科目・クラスの一方または両方をマスタと異なる内容に変更して保存する
  When: 保存が完了する
  Then: 変更した項目(科目・クラスのどちらか、または両方)だけがその週・そのマスの個別変更として保存され、時間割マスタおよび他の週の時間割には影響しない。教科担任制で「この週だけ別のクラスの授業を持つ」場合(例:火曜日に普段と異なる3-3のクラスで国語を行う)にも、科目とは独立にクラスだけを変更できる。変更しなかった項目は個別変更として保存されず、常にその時点のマスタの内容を参照し続ける(マスタが後から変わればそちらに追従する)

- Given: あるマスの個別変更を編集し、科目・クラスの両方をそのマスタの現在の内容と同じ値にして保存する
  When: 保存が完了する
  Then: その個別変更は自動的に削除され(「マスタの内容に戻す」を実行したときと同じ結果になる)、そのマスは以降マスタの内容を参照する。「変更あり」表示も消える

- Given: あるマスについて科目だけを個別変更している(クラスはマスタ追従のまま)状態で、後から時間割マスタ設定画面でそのマスのクラスが変更される
  When: マスタの保存が完了する
  Then: この週のクラスは変更後のマスタの内容に追従する(科目の個別変更はクラスの変更と無関係に維持される)。個別変更した科目がマスタの新しい科目と一致した場合のみ、科目側の個別変更も自動的に削除される(F4参照)

- Given: 週次時間割画面でマス編集モーダルを開いており、そのマスが個別変更されている
  When: 「マスタの内容に戻す」を選択して保存する
  Then: そのマスの個別変更が削除され、以降マスタの内容を参照する状態に戻る

- Given: 週次時間割画面でマス編集モーダルを開いている
  When: 科目の選択肢から「未設定(空きコマ)」を選んで保存する
  Then: その週・そのマスは科目なし(空きコマ)として個別変更が保存される。行事等でその週だけ授業がない場合に使う。マスタ自体や他の週には影響しない

- Given: 週次時間割画面でマス編集モーダルを開いている
  When: 「この授業を記録する」を選択する
  Then: そのマスの日付・時限を選択済みの状態で授業記録画面(F6)に切り替わる。モーダルでの未保存の変更を保存するものではない

### F6. 授業記録(メモ入力)

- Given: 授業記録画面で日付・時限を選択している
  When: 画面が表示される
  Then: その日・その時限の時間割(個別変更があればその内容)から科目とクラスが自動的に解決され、そのクラスの生徒一覧が氏名(出席番号順)のみの折りたたみ行として表示される。教科担任制でクラスごとに授業が異なる場合でも、あらかじめクラスを選び直しておく必要はない

- Given: 授業記録画面で生徒の一覧(氏名のみの折りたたみ行)が表示されている
  When: 生徒名の行をタップまたはクリックする
  Then: その生徒の行が展開し、メモ入力欄・共有区分トグル・その生徒専用の保存ボタンが表示される。他の生徒の行の開閉状態や入力内容には影響しない。クラス全員の氏名を一覧で見渡しながら、メモを書く生徒だけを個別に開いて記録できる

- Given: 授業記録画面の生徒一覧で、その日・その時限に既にメモが保存されている生徒がいる
  When: 一覧が表示される
  Then: 該当する生徒の行(折りたたみ状態でも)に、メモが保存済みであることを示すインジケーターが表示される

- Given: 授業記録画面で選択した日付・時限について、時間割(マスタまたは個別変更)の科目またはクラスが未設定(空きコマ含む)である
  When: 画面が表示される
  Then: メモ入力欄は表示されず、「この時間には科目またはクラスが設定されていないため、記録できません」という案内が表示される

- Given: 生徒の行を展開し、メモ入力欄にテキストを入力している
  When: その生徒の行にある保存ボタンを実行する
  Then: そのメモが生徒・科目・日付・時限に紐づいて記録され、生徒別メモ一覧に反映される。保存は生徒ごとに個別に行われ、他の生徒の入力内容や保存状態には影響しない(授業のたびに全員分をまとめて保存する必要はなく、メモを書いた生徒だけを保存すればよい)

- Given: 同じ生徒・同じ科目・同じ日付・同じ時限に対して既にメモが存在する
  When: 保存を実行する
  Then: 既存のメモが新しい内容で更新される(同一生徒・科目・日付・時限につきメモは1件とする)

- Given: メモ入力欄を新規に開く
  When: 共有区分を確認する
  Then: 共有区分は「共有する」が初期値として選択されている

- Given: メモ入力欄で共有区分を「共有しない」に変更してテキストを入力する
  When: 保存を実行する
  Then: そのメモは「非共有」として記録され、所感生成時のプロンプトから除外される

- Given: 共有区分が「共有する」の状態でメモを保存しようとしている
  When: 保存を実行する
  Then: メモ本文の内容によらず毎回、「本文に書いた氏名等の情報はそのままAIへ送信されます」という注意文が表示される

- Given: 週次時間割画面から、特定の日付・時限を選択済みの状態で授業記録画面に遷移した
  When: 画面内の「戻る」を選択する
  Then: 直前に表示していた画面(週次時間割画面)に戻る。「戻る」は直前の1画面のみを覚える単純な仕組みで、ブラウザの戻る/進むのような複数階層の履歴は持たない(F7の生徒別メモ一覧画面の「戻る」と同じ仕組みを共用する)

### F7. 生徒別メモ一覧

- Given: 生徒別メモ一覧画面を開いている
  When: 画面内のクラス選択で表示するクラスを切り替える
  Then: 生徒選択の候補が選択したクラスの生徒に絞り込まれる。この絞り込みはこの画面内でのみ有効で、他の画面のクラス選択状態には影響しない。生徒の氏名だけで選ぶより早く目的の生徒を選べるようにするための絞り込みである

- Given: 生徒別メモ一覧画面で生徒と「日付順」表示を選択している
  When: 一覧が表示される
  Then: その生徒の全メモ(共有区分を問わず)が日付の新しい順に、科目名・時限・共有区分とともに一覧表示される

- Given: 生徒別メモ一覧で、あるメモの共有区分表示を操作する
  When: 「共有する」「共有しない」を切り替えて保存する
  Then: そのメモの共有区分が更新され、以降の所感生成に反映される。あわせて「過去にAIへ送信済みの内容そのものは取り消せません」という注意文が表示される

- Given: 生徒別メモ一覧画面で生徒と「教科別」表示を選択している
  When: 一覧が表示される
  Then: その生徒のメモが科目ごとにグループ化され、各グループ内は日付の新しい順に表示される

- Given: 生徒別メモ一覧で既存メモを編集する
  When: 変更内容を保存する
  Then: そのメモの内容が更新され、更新前の内容は表示上残らない

- Given: 生徒別メモ一覧で既存メモを削除する
  When: 削除を実行する
  Then: そのメモが一覧から削除され、以降の所感生成の対象から除外される。既に保存済みの所感(F11)はスナップショットのため、この削除による影響を受けない

- Given: 生徒名簿画面または授業記録画面から、特定の生徒を選択済みの状態で生徒別メモ一覧画面に遷移した
  When: 画面内の「戻る」操作を行う
  Then: 直前に表示していた画面(生徒名簿画面または授業記録画面)に戻る。「戻る」は直前の1画面のみを覚える単純な仕組みで、ブラウザの戻る/進むのような複数階層の履歴は持たない

日付順・教科別以外の絞り込み(キーワード検索、共有区分によるフィルタ等)は実装しない(未決事項を参照)。

### F8. アカウント認証

- Given: 未ログイン状態でツールにアクセスする
  When: ログイン画面でメールアドレスと新しいパスワードを入力してサインアップを実行する
  Then: アカウントが作成されてログイン状態になり、以後そのアカウントに紐づくデータ(クラス・生徒・時間割・メモ・所感)のみが表示される。メールアドレスの確認(確認メールのクリック)は不要で、サインアップ直後から利用できる

- Given: 既に登録済みのメールアドレスで再度サインアップを行う
  When: サインアップを実行する
  Then: 「このメールアドレスは既に登録されています」というエラーが表示され、アカウントは作成されない

- Given: 登録済みのメールアドレスとパスワードでログイン画面から入力する
  When: ログインを実行する
  Then: 認証が成功し、そのアカウントに紐づく既存データが表示される

- Given: 誤ったメールアドレスまたはパスワードでログインを試みる
  When: 認証が失敗する
  Then: 「メールアドレスまたはパスワードが正しくありません」というエラーが表示され、ログインできない

- Given: ログイン中の教員がログアウト操作を行う
  When: ログアウトが完了する
  Then: 未ログイン状態に戻り、ログイン画面が表示される。再ログインするまでデータにアクセスできない

- Given: ログイン画面で「パスワードを忘れた場合」からメールアドレスを入力する
  When: リセット申請を実行する
  Then: 入力したメールアドレス宛にパスワードリセット用のリンクが送信される旨のメッセージが表示される。登録済みかどうかにかかわらず同一のメッセージを表示し、登録メールアドレスの存在を外部から推測されないようにする

- Given: パスワードリセットリンクからアクセスし、新しいパスワードを入力する
  When: 変更を実行する
  Then: パスワードが更新され、新しいパスワードでログインできるようになる

- Given: 未ログイン状態で、ログイン・サインアップ・パスワードリセット以外の画面(クラス管理、時間割等)に直接アクセスしようとする
  When: アクセスを試みる
  Then: ログイン画面にリダイレクトされる

### F9. 所感生成(APIキーによる直接呼び出し)

AIプロバイダ・モデル・APIキーの設定は教員1人につき常に1件のみ保持され、複数プロバイダ分を並行して保持することはない(新規登録・更新は既存設定への上書きとなる)。

所感はクラス単位の一覧画面(所感管理画面)で編集する。教員は画面上部でクラスと対象期間(開始日・終了日)を指定し、そのクラスに所属する生徒全員の氏名と所感入力欄が一覧表示される(各生徒の行は独立して編集・保存できる)。AI生成・プロンプトコピーの操作は各生徒の行内で折りたたまれており、必要なときだけ開く(詳細は`docs/design/screens.md`参照)。

- Given: 所感管理画面でクラスと対象期間(開始日・終了日)を指定している
  When: 教員が設定画面でAIプロバイダ(OpenAI、Anthropic、Google Geminiのいずれか)・使用するモデル・APIキーを登録済みで、特定の生徒の行でAI生成セクションを開き、目安の文字数を指定して生成を実行する
  Then: 指定した期間内のその生徒の「共有する」区分のメモのみをもとにしたプロンプトがバックエンド(Hono)経由で登録済みのAIプロバイダ・モデルに送信され、目安の文字数を意識した所感文がその生徒の所感入力欄に反映される。APIキーはバックエンド側で復号して使用し、ブラウザから直接AIプロバイダへ送信されることはない。生成後の文字数の自動検証・再生成は行わない。この時点では所感としてまだ保存されない(保存の挙動はF11を参照)

- Given: 設定画面でAIプロバイダ・モデル・APIキーを新規登録または更新する
  When: 保存を実行する
  Then: 入力されたAPIキーはバックエンド経由でサーバー側で暗号化されてSupabase DBに保存される。保存後、画面にAPIキーの平文は再表示されない

- Given: AI呼び出しの結果、APIから認証エラーまたはレート制限エラーが返る
  When: エラーが発生する
  Then: エラー内容が教員に表示され、所感は保存されずに直前の状態が維持される

- Given: 対象期間内にその生徒の「共有する」区分のメモが1件も存在しない
  When: その生徒の行でAI生成セクションを開く
  Then: 送信可能なメモが存在しない旨のメッセージが表示され、AIへの送信は行われない

### F10. 所感生成(プロンプトコピー運用)

- Given: 教員がAPIキーを設定していない
  When: 所感管理画面で対象期間を指定した状態で、特定の生徒の行でAI生成セクションを開く
  Then: 指定した期間内の「共有する」区分のメモをもとに生成したプロンプト文字列(生徒名は仮名コード)が表示され、コピーボタンでクリップボードに取得できる

- Given: 設定画面でプロンプトのひな形を編集する
  When: 編集内容を保存する
  Then: 以後の所感生成(直接呼び出し・プロンプトコピー運用の両方)で、保存したひな形をもとにプロンプトが組み立てられる。ひな形の初期値は本ツールが用意する固定文言とする

- Given: 教員が外部のAIチャットサービスから得た所感文をAI生成セクションの貼り付け欄に入力する
  When: 「所感欄に反映」を実行する
  Then: 貼り付けたテキストがそのまま、その生徒の所感入力欄(常時表示のテキストエリア)に反映される(仮名コードの検出・実名への置換は行わない。生成される所感文は生徒個人を特定する氏名・仮名コードを本文中に含まない前提のため)。この時点では所感としてまだ保存されない(保存の挙動はF11を参照)

### F11. 所感の確認・編集・保存・履歴閲覧

所感管理画面はクラス単位・対象期間単位で編集する。画面上部でクラスと対象期間(開始日・終了日)を指定すると、そのクラス全員分の所感入力欄が一覧表示される。各行の所感入力欄には、その生徒・その期間の組み合わせで既に保存されている所感があればその内容が初期表示され、なければ空欄になる(詳細は`docs/design/screens.md`参照)。

所感は生徒と対象期間(開始日・終了日)の組み合わせごとに1件保存される。同じ生徒でも期間が異なれば別レコードとして保持され、学期をまたいで過去の所感を参照できる。所感に「確定」のような別状態は設けず、保存後もいつでも再編集・再生成できる。所感は生成・保存した時点の内容を独立したレコードとして保持するスナップショットであり、元になったメモを後から編集・削除しても、既に保存済みの所感の内容には影響しない。

- Given: 所感管理画面でクラス・対象期間を指定し、ある生徒の所感入力欄が空欄(その生徒・その期間の所感が未保存)の状態である
  When: AI生成・プロンプトコピー運用・手動入力のいずれかで内容を入力し、その行の保存を実行する
  Then: その生徒と対象期間の組み合わせに紐づく所感として新規に記録され、作成方法(AI生成・直接呼び出し/AI生成・プロンプトコピー運用/手動作成)が記録される

- Given: 所感管理画面である生徒・対象期間の所感入力欄に、既に保存済みの内容が初期表示されている
  When: 教員がその内容を編集(またはAI再生成・貼り付けで置き換え)し、その行の保存を実行する
  Then: 編集後の内容で、その生徒・その期間の所感が更新される。同じ生徒の他の期間の所感には影響しない。上書き確認ダイアログは表示しない(対象期間は画面上部で編集前から一意に確定しており、保存操作自体が既存レコードへの意図的な更新であるため、生徒別メモ一覧・時間割マスタ設定のような「異なる操作が同じ対象に衝突しうる」場面には当たらない)

- Given: 所感管理画面である生徒の行を開いている
  When: 「過去の所感を見る」を開く
  Then: その生徒についてこれまでに保存された所感のうち、画面上部で指定中の対象期間以外のものが、対象期間(開始日〜終了日)ごとに新しい順で一覧表示され、それぞれの作成方法(直接生成・プロンプトコピー運用・手動作成)と最終更新日時が併記される(閲覧専用。編集する場合は画面上部の対象期間を該当の期間に変更する)

### F12. プライバシー配慮(自動匿名化)

- Given: 教員が所感生成(直接呼び出しまたはプロンプトコピー運用)を実行する
  When: プロンプトが生成される
  Then: 生徒名は仮名コード(学年1桁(「特支」クラスの場合は「特」の1文字)+組番号2桁(ゼロ埋め)+出席番号2桁(ゼロ埋め)をハイフンで連結、例:1年生・組番号3・出席番号10番→「1-03-10」、特支クラス・組番号4・出席番号7番→「特-04-07」)に置き換えられた状態でプロンプトに含まれる

- Given: 直接呼び出しでAIから所感文の応答が返る
  When: 応答を画面に表示する
  Then: AIから返った応答テキストをそのまま画面に表示する。生成される所感文は生徒個人を特定する氏名・仮名コードを本文中に含まない前提のため、応答内の仮名コードを検出して実名に置き換える処理は行わない

- Given: 教員が所感生成を初めて実行する
  When: 生成ボタンを押す
  Then: 「共有する」区分のメモが仮名化された状態で外部のAIサービスに送信される旨の注意文が表示される

### F13. 保存エラー対応

- Given: DBへの書き込み中に通信エラーまたはサーバーエラーが発生する
  When: 保存を実行する
  Then: 保存に失敗した旨のエラーが表示され、直前の状態が維持される(データの不整合な部分保存は行わない)。教員は時間をおいて再度保存を試みることができる

### F14. データエクスポート

教員が生徒ごとのメモ・所感を長期的に手元に保管しておけるよう、アカウントに紐づく全データをエクスポートする機能を設ける。取り込み(インポート)による復元機能は持たない(スコープ外を参照)。

- Given: 設定画面を開いている
  When: 「全データをエクスポート」を実行する
  Then: そのアカウントに紐づくクラス・生徒・科目・時間割マスタ・週次時間割の個別変更・メモ・所感・プロンプトひな形が、生徒ごとにメモ・所感がまとまる形でJSON形式のファイルとしてダウンロードされる。AIプロバイダ設定(APIキーを含む)はエクスポート対象に含めない

- Given: エクスポートを実行しようとしている
  When: 実行前に確認画面を表示する
  Then: 「ダウンロードされるファイルには生徒の氏名など個人情報がそのまま含まれます。ファイルの保管・取り扱いには十分注意してください」という注意文を表示したうえで、教員が続行を選択した場合のみエクスポートを実行する

## 非機能要件

- **データ永続化**: すべてのデータをSupabase(PostgreSQL)に保存する。ブラウザのlocalStorageは永続データストアとしては使用しない。教員が選択したAIプロバイダへ、バックエンド経由で仮名化済みプロンプト(「共有する」区分のメモのみ)を送信する場合を除き、外部にデータを送信しない
- **想定データ規模・利用規模**: 現時点では個人利用〜身内の少数教員(数人程度)によるテスト運用を想定する。1教員あたり数クラス×数十人の生徒、学期を通じて生徒1人あたり数十件程度のメモを想定する
- **対応環境**: PCおよびタブレットのブラウザで動作する。対応ブラウザはChrome、Edge、Safariの最新版とする。スマートフォンでの利用は対象外とする
- **パフォーマンス**: 厳密な数値目標は設けない。通常のWebアプリケーションとして体感的にストレスなく操作できることを目安とする
- **タイムゾーン**: 週番号・起算日・「今日」の判定など日付に関わる計算はすべて日本時間(JST, UTC+9)で固定して行う。サーバー(Vercel)の実行環境のタイムゾーンに関わらずJSTで統一する
- **アカウント・認証**: Supabase Authによるメールアドレス+パスワード認証。誰でも自由にサインアップ可能。サインアップ時のメールアドレス確認(確認メールのクリック)は行わない。パスワードを忘れた場合はメールでのパスワードリセット機能を提供する。アカウント削除(退会)機能は今回のスコープ外とする。招待制・許可リストなどのサインアップ制限は設けない。現時点の想定利用規模(身内の少数によるテスト運用)ではこのリスクを受容する。利用規模が拡大する場合はサインアップ制限の導入を再検討する
- **マルチテナンシー**: 1アカウントは1教員分のデータのみを参照できる。Supabaseの行レベルセキュリティ(RLS)により、他教員のデータには一切アクセスできないようにする。複数教員間でのデータ共有・同時編集・権限管理は行わない
- **同時編集**: 同一教員が複数端末から同時に同じデータ(メモ・時間割・所感等)を編集した場合、競合検知は行わず、最後に保存した内容が反映される(Last-Write-Wins)。複数端末からの同時編集に対する警告表示・排他制御は実装しない
- **AIプロバイダ連携**: 対応するAIプロバイダはOpenAI、Anthropic、Google Geminiとする。教員は設定画面でプロバイダと使用するモデルを選択する。各プロバイダの初期選択モデルはコストと品質のバランスを重視した中位モデルとし、教員が変更できる。AIプロバイダへの呼び出しはバックエンド(Hono)経由で行い、ブラウザから直接AIプロバイダへリクエストを送信することはない。これにより、プロバイダ側のCORS対応状況には依存しない
- **APIキーの保存**: AIプロバイダのAPIキーは、バックエンド経由でサーバー側で暗号化されSupabase DBに保存される。保存後、画面には再表示されない。設定画面に、APIキーがサーバー側で暗号化されて保存される旨、および定期的なキーの見直し・失効を推奨する旨を明記する。暗号化に使う鍵はVercelの環境変数(Environment Variables)で管理し、全教員共通の鍵を用いる
- **プライバシー配慮**: 所感生成時にAIプロバイダへ送信する生徒名は、オプションではなく常に仮名コード(学年1桁(「特支」クラスは「特」の1文字)+組番号2桁+出席番号2桁をハイフンで連結)に置き換える。実名がAIプロバイダへ送信されることはない。メモは「共有する」/「共有しない」の区分を持ち、初期値は「共有する」である(教員が明示的に除外しない限りメモは所感生成の対象になる、利便性を優先した設計判断)。「共有しない」メモは送信対象から除外される。メモ本文に教員が自由に書いた氏名等の記述内容そのものは自動検出・自動置換の対象外であり、共有区分が「共有する」のメモを保存するたびに、内容によらず毎回「本文に書いた氏名等の情報はそのままAIへ送信されます」という注意文を表示する
- **データ消失対策**: データはSupabase DBに保存されるため、ブラウザのキャッシュ削除やiOS Safari等の一定期間アクセスがない場合のサイトデータ自動削除の影響を受けない。Supabaseの無料プランには自動バックアップ・Point-in-Timeリカバリは含まれず、本ツールは自動バックアップの手段を持たない。誤操作や障害による全データ消失のリスクを受容したうえで無料プランのまま運用する。有料プランへの移行は導入しない。その代わり、教員が任意のタイミングで全データをJSON形式でエクスポートできる機能(F14)を手動バックアップの手段として提供する。自動バックアップではないため、教員が自分でエクスポートを実行しない限りデータは保護されない
- **運用コスト**: Supabase・Vercelともに無料プランの範囲内での運用を前提とする。無料プランの上限(データ容量、月間アクティブユーザー数、API呼び出し回数等)に達した場合の対応は、その都度検討する
- **エラー監視・ログ**: 専用の監視ツール(Sentry等)は導入せず、Vercel・Supabaseが標準で提供するログ機能を利用する
- **可用性**: 本ツールはVercel(フロントエンド・バックエンド)およびSupabase(DB・認証)の可用性に依存する

## スコープ外(やらないこと)

- 生徒本人または保護者向けの閲覧・入力機能
- 既存の通知表システムや成績管理システムとの自動連携
- スマートフォン向けのUI最適化
- 複数の教員間でのデータ共有、同時編集、権限管理
- 音声入力や画像添付など、テキスト以外の形式でのメモ記録
- APIキーを持たない教員に対する、ツール側でのAI所感の完全自動生成(この場合はプロンプトコピー運用で対応する)
- 生成した所感文の正確性・妥当性に関するツール側での自動チェック
- 年度更新に伴う進級処理、および学期途中の生徒の転入出処理(年度が変わる場合は新しいクラスを作り直す運用とする)
- メモ本文の自由記述テキストからの氏名・個人情報の自動検出および自動マスキング
- 全データのJSONインポート(取り込み・復元)機能。エクスポート(書き出し)はF14として提供するが、そこからデータを復元する機能は持たない
- アカウント削除(退会)機能
- サインアップ時のメールアドレス確認(ただしパスワードリセットは提供する)
- 専用のエラー監視・APMツールの導入(プラットフォーム標準ログで運用する)
- 所感の「確定」(ロック)機能。所感は保存後もいつでも再編集・再生成で上書きできる
- 時限が7時限以上ある学校、隔週土曜授業など、1〜6時限・月〜金以外の時間割構成への対応
- 生徒の所属クラス変更(誤登録の訂正を含む)。クラスを変更したい場合は生徒の削除・再登録で対応する
- 複数端末からの同時編集に対する競合検知・警告・排他制御(Last-Write-Winsで割り切る)
- サインアップの招待制・許可リストなどのアクセス制限
- Supabase無料プランを超えるバックアップ体制(自動バックアップ、Point-in-Timeリカバリ等)の整備

## 用語集

| 用語 | 定義 |
|---|---|
| 時間割マスタ | 標準として設定する曜日×時限の科目・クラス割当。教員1人につき1つ持ち、クラスには依存しない(教科担任制対応)。特定の週で変更がない限り、この内容が毎週自動的に適用される |
| 科目 | 時間割マスタ・週次時間割の個別変更・メモで割り当てる教科。科目管理(F3)で教員ごとに登録・編集・削除する自由入力ではないマスタ項目。時間割やメモで使用中の科目は削除できない |
| 一括モード | 時間割マスタ設定画面の入力モードの1つ(初期値)。画面上部でクラスを1回選択すると、時間割マスタの全マスに同じクラスが適用される。単一クラスを担任する教員(小学校等)向け |
| 教科担任制モード | 時間割マスタ設定画面の入力モードの1つ。マスごとに科目とクラスを個別に選択できる。複数クラスを受け持つ教員向け。保存されるデータ構造自体は一括モードと共通で、モードは入力方法の違いにすぎない |
| 起算日 | 週次時間割の週番号を計算する基準となる開始日。教員1人につき1つ持つ(クラスごとには持たない)。この日を含む月曜始まりの週が「第1週」となる。授業記録(メモ)が1件以上保存されると通常の編集はできなくなるが、「年度を更新する(起算日を再設定する)」という明示的な操作を経由すれば再設定できる |
| 週次時間割 | ある特定の週について実際に適用される時間割。時間割マスタの内容がデフォルトとして入り、その週だけの変更(科目・クラスのいずれか、または両方)があれば個別に上書きできる |
| クラス | 学年・クラス表示名で識別される生徒の集合。1教員が複数のクラスを管理できる。時間割マスタとは独立して管理され、時間割マスタの各マスから参照される |
| 特支 | クラス作成時に学年の代わりに指定できる特別な値。特別支援学級等、特定の学年に属さず学年をまたぐ生徒で構成されるクラス(例:ひまわり組)に使う。仮名コードの学年部分では「特」の1文字として扱う |
| 組番号 | クラスごとに自動付与される、内部管理用・仮名コード生成用の連番(同一学年内でのクラス作成順。「特支」は1つの学年区分として扱い、「特支」内での作成順で採番する)。表示名(「ひまわり組」等)とは別に保持する。クラス編集で学年を変更した場合は、変更後の学年区分内で未使用の番号に再採番される。表示名のみを変更した場合(学年は変更しない場合)は組番号は変わらない |
| メモ | 特定の生徒・科目・日付・時限に紐づく自由記述のテキスト。「共有する」/「共有しない」の共有区分を持つ(初期値は「共有する」) |
| 共有区分 | メモごとに設定する、所感生成時にAIへ送信してよいかどうかを示す属性。生徒別メモ一覧から後から変更できる |
| 所感 | 教員が指定した期間の「共有する」メモをもとに生成、または手動で作成する、目安の文字数のコメント文。生徒と対象期間(開始日・終了日)の組み合わせごとに1件保存され、同じ生徒でも期間が異なれば別レコードとして保持される。保存後も再編集・再生成による上書きが可能で、内容を確定してロックする機能は持たない |
| 直接生成 | 教員が登録したAPIキー・モデルを使い、バックエンド(Hono)経由でAIプロバイダのAPIを呼び出して所感を生成する方式 |
| プロンプトコピー運用 | APIキー未設定の場合に、所感生成用のプロンプト文字列を教員がコピーし、外部のAIチャットサービスに貼り付けて所感を得る方式 |
| 仮名コード | AIプロバイダへの送信時に生徒の実名の代わりに使う識別子。学年(1桁。「特支」クラスは「特」の1文字)+組番号(2桁ゼロ埋め)+出席番号(2桁ゼロ埋め)をハイフンで連結した文字列(例:1年生・組番号3・出席番号10番→「1-03-10」、特支クラス・組番号4・出席番号7番→「特-04-07」)。項目ごとに固定桁数・区切り文字で連結するため、組番号や出席番号が2桁になっても他の生徒のコードと衝突しない。生徒名簿画面で各生徒の仮名コードを確認できる |
| アカウント | Supabase Authで管理される、教員1人に対応するログイン単位。メールアドレスとパスワードで認証する。1アカウントは1教員分のデータのみを保持し、他アカウントのデータにはアクセスできない |

## 未決事項

- パフォーマンスに関する具体的な数値目標は設けない方針としたが、実際に使ってみて体感的に遅いと感じた場合の対応閾値は未確定
- 所感の目安文字数の指定方法(あらかじめ用意した選択肢から選ぶか、自由入力とするか)は未確定
- 仮名コードの各項目は2桁を前提に固定桁数化したが、1学年100クラス以上、または1クラス100人以上という桁あふれのケースの挙動は未定義(発生可能性は低いと想定しており、発生時に対応する)
- 生徒別メモ一覧のフィルタ機能(キーワード検索、共有区分での絞り込み等)の要否・仕様は未確定。実装する場合は将来の追加実装候補とする
- AIプロバイダごとに選択可能なモデルの具体的な一覧(既定モデル名を含む)は未確定
- Supabase無料プランの上限(DB容量、月間アクティブユーザー数、API呼び出し回数等)に達した場合の具体的な対応方針は未確定
- 所感の保存キーは生徒×期間(開始日・終了日の完全一致)としているため、前回と数日だけずれた期間で再生成した場合は別レコードとして保存され、上書き確認の対象にもならない。期間の重複や近接をどこまで「同一期間」とみなすかの許容範囲は未確定
- 科目管理の初期値が未確定。新規アカウント作成時に科目一覧を空の状態で始めるか、代表的な科目(国語・算数・理科・社会等)をあらかじめ用意しておくかは未決定
